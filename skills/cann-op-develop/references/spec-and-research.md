# 规格与参考

## 调研产出

查找成熟库/其他仓库的同名算子、基础算子组合，再检查目标 CANN 仓库中可借鉴的邻近算子。记录公开源码/文档地址、版本或 commit、数学差异、许可证及归属要求、适用平台和拟借鉴部分。不要把上一个项目的路径或版本作为新任务默认值。

将参考分为：

- **语义参考**：决定公式、边界、舍入、输出含义；可能较慢。
- **实现参考**：提供分块、缓存、并行、接口或测试组织；必须验证其适用条件。
- **性能基线**：语义等价且通过同一精度要求的可运行实现；优先同设备原生算子或等价组合。

例如有限高斯二阶导 FIR 与高斯平滑后离散 Laplacian 并不天然等价。定义不同的实现可以展示误差与时间，但不能直接据此裁决同语义加速比。组合实现也可成为有效性能基线，不能仅因有多次下发就排除。

数据格式表表头保持：

```text
序号 | Op | Classify | Name | Type | Shape | TypeRangeAll | Attr_Default_value | Format类型 | 参考算子&算子输入说明 | 参考资料
```

每个输入、输出、属性独立一行。`Classify` 使用 INPUT/OUTPUT/ATTR；填明可选性、默认值、输入/输出 dtype 配对及 shape 解释。沿用用户 XLSX 模板；没有模板或 Excel 工具时可先用同列 Markdown/CSV，并说明格式，不能把 CSV 改后缀伪装成 XLSX。

## 开发前长期约定

下列内容以短表写入支持目录 README。由调研可确定或用户已给出的直接填写；只问缺失且有实际分歧的内容。

| 内容 | 应明确的决策 |
| --- | --- |
| 数学语义 | 公式、核生成/归一化、边界、舍入/饱和、默认值、输出含义 |
| 支持范围 | 必做/可选功能，dtype 配对，shape/layout，batch/channel，连续性，动态/空 tensor，原地与别名限制 |
| 非正常输入 | 非法属性、NaN/Inf、未知维度、资源不足、超大尺寸的处理；不适用项略去 |
| 精度 | golden 版本、比较域、atol/rtol、通过比例、其他指标、整数是否逐元素相等、特殊值策略 |
| 性能 | 重点矩阵、基线、设备驻留/端到端口径、目标收益与可接受退化；无目标则报告结果，不自造达标线 |
| 环境与权限 | 目标 SoC、CANN、执行入口、允许使用的卡、修改范围、共享环境边界、是否授权推送/发 PR |
| 工程交付 | 仓库/基线、算子名称、路径、必需测试和文档、fork/分支；提交身份可在首次提交前补齐 |

精度标准先依据数学输出和业务需求提出，再用独立 golden、小规模极值探针检查可行性。需要探针才能决定的事项在正式优化前收敛，不长期留为“待定”。探针可以提出标准调整，但不能静默批准变更。

浮点常用比较形式为 `abs(actual - expected) <= atol + rtol * abs(expected)`；数值由任务确定。近零区需绝对误差约束。RMSE、最大误差和通过比例是不同指标，不能互相替代。对精确计数、索引、mask、二值结果通常采用精确比较，不能因底层用了浮点就改为宽松容差。

## 变更规则

冻结的是对外行为和验收约定，不是实现方案。可以调整 tiling、核数、缓冲布局、结构性 UT 断言及算法实现，保留覆盖目标并解释变化。改变接口、支持域、golden 定义或容差必须获得用户决定。已有测试被证明错误时，修正测试并保留反例，不把“测试失败”一概等同于生产代码错误。
