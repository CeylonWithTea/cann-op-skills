# 验证与性能

## 分层验证

| 层次 | 重点 |
| --- | --- |
| Host UT | 注册、InferShape、dtype、参数拒绝路径、未知维度、溢出防护、tiling/workspace/UB 预算边界 |
| Kernel UT/仿真 | 调用真实 kernel；分支、尾块/halo、搬运对齐、缓冲复用、整数转换和实际溢出回退 |
| 实机数值 | 匹配的新包与头文件/库；完整输出对拍、输入只读、batch 隔离及适用的重复/并发行为 |
| 性能 | 正确性合格后的固定代表矩阵；同条件基线和上一成功 demo 比较 |

Host 通过不证明 kernel 正确；CPU 仿真也不证明设备同步正确。无法执行某一层时说明原因和风险，不把“未验证”写成通过。关键路径缺口应修复或获得明确的交付范围决定。

用例从规格和实际分支产生：dtype × 算法模式，最小/空/退化形状，tile 前后边界，多 batch，大半径/窗口，舍入临界点、极值、长宽图和真实生产输入。资源边界按预算的恰好可行/刚好不可行检查，避免只测常见方图。溢出、暂停恢复、多核采纳等路径要证明被触发；不能将测试调小容量后的触发等同于生产容量的自然触发。

golden 从数学定义独立实现，避免复制生产侧 tiling、滑窗、索引或补偿路径。对复杂数值可增加第二个独立参考，普通算子无需机械要求双 golden。显式检查 NaN/Inf，按规格逐项比较特殊值；`diff > threshold` 在 diff 为 NaN 时可能假通过。

优化中加入有数学依据的变形用例，例如不同 seed、翻转、batch 重排和重复调用；注意边界、方向或阈值可能破坏某些变形关系，不能无依据地要求输出不变。测试可以修改内部结构断言，但保留输出覆盖、资源上限、回退和独立参考等行为保障。

运行记录至少有命令、源码标识、用例集、数量、退出码、结果位置。报告 UT 测试组与参数组合时区分计数；重叠套件不相加成独立用例数。

## 性能基线与计时

优先级：同 NPU 的原生实现 → 同 NPU 的等价基础算子组合 → 其他设备成熟实现；没有等价外部基线时使用上一成功 demo。即使存在外部基线，也保留版本间比较。组合基线需计入完整计算链，不能只选其中一个 kernel。

被测与基线使用相同实际输入、参数、dtype、边界和输出定义，并先通过同一精度标准。参考库不支持的 dtype 单独报告，不隐式转型后混比。若多种等价基线可用，预先约定选择规则，逐例记录所选实现，避免事后挑弱基线。

分开报告：

- profiler 的设备任务时间（说明求和还是关键路径）；
- 设备 event 区间（可能包含调度间隙，不能自动叫纯 kernel 时间）；
- 端到端时间（明确是否含 H2D/D2H、分配、工作区查询、同步和预处理）。

GPU/NPU 异步调用要正确同步。保持同一统计口径，记录预热次数、测量次数、重复轮次、统计量、设备/软件版本及 CPU 线程/亲和性等影响项。不将历史项目的 2/5 或 10/50 次数固化为所有场景标准；根据稳定性增加样本。比较不同版本时尽量同批交替复测，避免设备负载与温度偏置。

逐例表建议字段：

```text
case_id, shape, dtype, attrs, candidate_version, baseline_impl, baseline_version,
metric, unit, candidate_time, baseline_time, previous_time,
baseline_speedup, previous_speedup, correctness, notes
```

加速比 = 对照耗时 / 当前耗时，大于 1 表示当前更快。附原始样本或可复核的统计摘要。缺失、不支持和失败用例分别标记，不填 0。几何平均只在共同、有效且口径一致的用例集合计算，公布数量和排除项；新增矩阵与旧矩阵的均值不能直接当作版本收益。

同时展示目标场景、慢例、最坏退化和波动。差异在测量噪声内则写“未确认收益”。不能为性能放松精度、删掉失败用例或只呈现最快单次。

## 裁决

正确性失败的版本不参与正式性能胜负裁决。功能迭代按功能目标验收并披露性能变化；优化迭代按预先确定的目标与退化约束验收。实验失败可保留有限诊断计时，但不得列为成功加速比。

更改同步、求和次序、类型转换、缓冲布局或 tiling 后，除受影响测试外，在封存与交付前回归当前支持范围。公共 API、输出约束或 kernel 变化使旧包验证失效；确保构建、安装、运行对应同一版本。
