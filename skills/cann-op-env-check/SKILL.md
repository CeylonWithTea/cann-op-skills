# CANN 环境确认

使用现有环境，输出可执行能力与缺口。默认只读检查，不安装依赖、不重建容器、不占用未知归属的卡、不修改共享环境。开发任务已有构建/测试授权时，可运行最小验证；单独要求“检查环境”时先做只读检查，实际运行能力无法验证则明确标注。

## 核对路径

1. **定位执行环境**：根据当前任务资料区分宿主机、容器、远程环境与本地模拟器。复用已指定的环境；多套候选且没有选择依据时，集中提出选择。目录名或当前 shell 只能证明当前状态，不能证明兼容性。
2. **工具链与目标**：核对主机架构、实际 CANN 版本/根路径、编译器、CMake/编译器发现路径、Python 解释器及测试依赖。读取目标仓构建帮助和依赖声明，不照搬历史 build 参数或 CANN 版本。
3. **设备**：核对型号、目标 SoC、驱动与运行时兼容要求、设备健康及占用；结合容器可见性与 runtime 逻辑编号确认物理卡映射。不能把“容器内 device 0”直接等同物理卡 0。查询不可用时写“未确认”，不能当成空闲。
4. **文件与安装**：检查源码/构建/结果目录的读写与宿主可读性；确认挂载到实际源码位置。每个项目用可区分的构建输出和私有安装位置，检查生成头文件、链接库、运行库及 vendor/package 是否来自同一版本。
5. **实际能力**：在已有授权内按任务需要进行最小构建、仿真或实机 smoke。只读检查通过不等同实测通过；编译成功不等同上板可用。已有有效结果与当前环境/源码一致时可以复用。

不预设 Docker privileged 模式、root 用户、物理卡号或固定安装路径。原生 Linux、已有容器和无 NPU 的仿真环境分别适配，只确认本任务需要的能力。

## 可选检查命令

按环境选用，命令不存在或权限不足时记录原因；不要为检查而自动提权或安装。

```bash
uname -m
command -v python3
python3 --version
command -v cmake
cmake --version
command -v ccec
command -v bisheng
command -v npu-smi
npu-smi info
# 需要容器且有权限时，仅查看相关容器
docker ps --format '{{.Names}}\t{{.Image}}\t{{.Status}}'
# 仓内核对当前参数
bash build.sh --help
```

编译器命令名称、版本查询方式和 CANN 安装元数据随发行版变化，按实际可用工具补查。允许通过平台的正常权限申请完成已授权的只读检查，不能绕过拒绝。

不整段转储环境变量、容器 inspect、Git credential 或 SSH 配置；只提取相关路径、版本、映射与权限事实，避免记录秘密。激活环境使用已确认的脚本或执行入口，不把“source 任意发现脚本”当成只读操作。

## 结论与复用

写入本任务 README 或已有环境记录的一小节：

```text
执行位置与激活入口：
工具链/解释器/依赖版本：
目标 SoC、设备映射和当前占用：
源码/构建/私有包/结果目录：
可构建 / 可仿真 / 可上板：各自标明已实测、仅静态检查或不可用。
缺口与影响：
复测入口与日期：
```

静态环境组合未变化时复用记录；上板前重新检查设备可用性，构建/安装后重新核对包身份。换机器、CANN、驱动、Python、容器挂载或 vendor 后重新核对受影响部分。环境修复超出既有权限时，说明具体修改及影响再询问；不能默认重装整套环境。
