# CANN 算子自审

基于规格、当前源码和可复现证据找缺陷，给出可执行的修复建议。可以在单 Agent 开发中作为独立审查步骤，不强制另起 Agent、审批节点或报告体系。

## 选择审查范围

- **迭代自审**：查看本次 diff 及必要调用链，优先检查被改变的索引、数据流、同步、类型和分支。输出可直接追加到迭代记录。
- **提交前检视**：以实际目标分支与最终提交差异为范围，覆盖接口、实现、测试、文档、示例、构建和发布资产。
- **评审整改**：从评论涉及的版本与触发条件出发，先确认当前是否仍存在；修复后使用相同反例和受影响回归复验。

已有开发授权时可在范围内修复；仅要求审查时先报告，不默认修改代码或提交评审评论。未授权或无条件运行的测试写为未验证。

## 审查顺序

1. 读取规格/精度约定、当前版本和 diff。沿注册 → InferShape → Tiling → Kernel → 调用示例/测试追踪参数与内存。不能因某一文件没有校验就断言全链路没有校验。
2. 根据 [历史缺陷检查表](references/defect-patterns.md) 选择适用项；API 约束以目标 CANN/SoC 版本的官方资料或可验证实现为准，不把历史案例的字节数、容量或写法当成所有平台规则。
3. 先检查高影响问题：越界、溢出、未初始化、同步/死锁、错误的数值和输出语义，再检查覆盖与工程完整性。
4. 对每个发现给出具体触发输入、相关代码位置、影响和建议。能复现的记录命令与结果；静态推导要写明前提；证据不足标为待核实。
5. 检查修复测试真正调用生产实现并触发目标路径；同时检查 golden 和比较器本身。实现与 golden 同样错、NaN 被比较器忽略，都不能算通过。

## 核心检查

- **契约一致**：dtype/shape/layout、batch/channel、属性、连续性、未知维度、空 tensor、optional、原地/别名、错误返回在所有层一致。
- **范围闭合**：Host 允许的每条路径都满足 Kernel 的整数范围、搬运字段宽度、对齐、UB、workspace 与实际访问上限。对尾块、fallback 和空核分别核算。
- **数据依赖**：缓冲重用、跨管线同步、多核 barrier、workspace 初始化及可见性正确；删屏障的性能收益不能代替正确性论证。
- **数值边界**：整型全值域转换与饱和、半整数取整、FP32 精确计数界限、近零抵消、极小数和特殊值与规格一致。
- **覆盖有效**：每个重要模式/dtype、拒绝路径、tile/UB 边界、多核与回退都有适合的可执行验证；只统计行覆盖率不足以证明这些路径正确。
- **交付可复核**：关键测试和 benchmark 可获取，ACLNN 头文件/符号确实生成或提供，示例可构建；README、接口文档、issue/PR 与最终提交一致；公共脚本和全局忽略规则没有夹带无关修改。

生成 ACLNN 或 binary 配置是合法工程方式；检查生成与打包链路，不以“缺手写文件”机械报错。性能不足与功能错误分开陈述，性能目标以任务约定为准。

## 结论格式

保持简短，可直接写入已有迭代记录：

```text
范围：基线、当前源码标识、审查文件/路径。
发现：严重度｜位置｜触发条件与影响｜证据｜修复/补测建议。
验证：实际运行了什么，哪些仅静态检查，哪些无法验证。
结论：可进入下一阶段 / 需修复 / 证据不足，以及剩余限制。
```

严重度按影响判断，历史评论的 Blocker/Major/Minor 仅作来源信息。没有发现也要说明检查范围，不能宣称不存在任何 bug。失败或待核实项不能自动标为解决；误报保留简短反证，避免重复提出。
